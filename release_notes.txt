Release Notes — EDR Telemetry Store Explorer
Version 26.10.0.131


DARK MODE
---------
- Scrollbars now styled for dark mode in Chrome and Edge (WebKit ::-webkit-scrollbar)
  and Firefox (scrollbar-color). Track uses sidebar background (#161b22); thumb is
  dark grey (#484f58) with a lighter hover state (#6e7681).
- Hunt Target Definitions regex pattern and field name display spans now use
  --bs-tertiary-bg / --bs-body-color so they render correctly in dark mode instead
  of remaining light grey.

HUNT — IP ADDRESS REGEX
------------------------
- IP address regex now validates each octet to 0–255, rejecting values such as
  999.2.3.45 or 256.x.x.x that were previously accepted.
- Leading zeros are accepted per octet (e.g. 026.003.193.004, 26.003.233.5).


Version 26.09.0.130


HUNT — IOC TYPE PREFIX (FREE-TEXT MODE)
----------------------------------------
- Lines starting with a recognized type keyword force the IOC type for that line,
  overriding auto-detection. Supported separators after the keyword: space, comma,
  or colon (with optional surrounding whitespace). Everything after a second comma
  is treated as a note/description and ignored.
- Supported keywords (case-insensitive):
    file / filename / file_path_name → Process / File
    domain / dns                     → DNS
    url                              → URL
    ip / ip address                  → IP
    sha256 / sha256 hash / sha2 / sha-256 / sha2 → SHA256
    sha1 / sha1 hash / sha-1         → SHA1
    md5 / md5 hash                   → MD5
    registry_path_key                → Registry
- Examples:
    file,DF0E2D20B4E8473699.TMP
    ip address ,5.39.222.67 ,C2 Server
    SHA256 hash,b25b87cfcedc69e27570afa1f4b1ca85aab07fd416c5d0228f1fe32886e0a9a6,PortStarter DLL
- Wildcards in paths: use * or <placeholder> (e.g. <user>) in a path — the process
  normalizer converts <…> to * automatically. Wildcard segments generate an AND query
  requiring all non-wildcard parts to appear in the field value, e.g.
  "C:\Users\*\Downloads\sh.ps1" matches any username in that path.

HUNT — PROCESS / FILE SEARCH FIX
----------------------------------
- Bare filenames (e.g. "firefox.exe") now use wildcard-contains queries instead of
  match_phrase, so they correctly hit full stored paths (keyword-mapped fields) on
  pFullName, cmdLine, fileAttributes.path, and procFileAttrs.path. Case-insensitive.


Version 26.09.0.129


HUNT
----
- Process/File IOC type: bare filenames (e.g. "firefox.exe") now use a wildcard-contains
  query instead of match_phrase, so they correctly match anywhere inside a stored full
  path (e.g. "C:\Program Files\Mozilla Firefox\firefox.exe") on keyword-mapped fields.
  Match is case-insensitive. Affects all four search fields: pFullName, cmdLine,
  fileAttributes.path, procFileAttrs.path.

LIVE TAIL — TABLE TAB
---------------------
- Stats bar now shows the tail start time: "Live · 12:13:44 · 425 total · 0 loaded · since 12:10:22".
- "Loaded" counter starts at 0 when tail begins and counts only events received via
  polling (not the 500-event initial load).
- Table tab no longer silently fails to update when the initial load returned 0 results;
  the full table structure is now rebuilt on the first poll that delivers new events.
- Right-click context menu on Table rows now correctly references the displayed event
  (tblHitsRef) instead of lastResults, which is never updated by tail polls.


Version 26.09.0.128


COPY BUTTONS — EVENT DETAILS & RESULTS
--------------------------------------
- Table tab event-detail panel: "Copy Raw JSON" and "Copy CSV" buttons added to
  the right side of the EVENT DETAILS caption. Copy the currently open event.
- Results tab event cards: "Copy Raw JSON" and "Copy CSV" buttons added beside the
  existing "Raw JSON" toggle in each card header.
- CSV for a single event is emitted as field,value rows (one field per line);
  nested objects flatten to dot-notation keys, arrays are JSON-encoded, and
  _index / _id are included. Buttons flash "Copied!" on success and fall back to
  a legacy copy path in insecure/older-browser contexts.

RESIZABLE EVENT DETAILS PANEL
-----------------------------
- The Table tab EVENT DETAILS panel can now be resized by dragging its left edge.
  Width is clamped (min 260px, table keeps >=200px) and persists across sessions.

GROUP BY
--------
- Results now scroll when they exceed the visible area (previously the overflow
  was unreachable).
- New "Copy Results (CSV)" button exports all buckets in the current sort order:
  each group-by field plus Count, Hosts, First Seen, Last Seen.

OPTIMIZATION
------------
- "Copy CSV" button on the Daily Summary table (Day, Events, Unique GUID, Avg,
  including the totals row).
- "Copy CSV" button on every per-day Field A / Field B card (Value, Count, Percent).

Version 26.08.0.125


OPENIOC TAB
-----------
- New OpenIOC tab for running FireEye/Trellix .ioc files directly against the EDR
  Telemetry OpenSearch cluster.
- File tree loads the local OpenIOC/ directory with full tactic/OS/confidence hierarchy.
  Supports individual file selection and entire folder selection with cascade.
- Tri-state folder checkboxes: checked (all files), unchecked (none), indeterminate
  (some). Selecting a parent folder selects all descendant .ioc files automatically.
- Real-time filter input narrows the tree by file name as you type.
- "Select all" / "Deselect all" controls. Selected file count shown at all times.
- Parses the OpenIOC boolean criteria tree (AND/OR Indicators, IndicatorItem leaves).
  Supports all 7 event types: processEvent, fileWriteEvent, ipv4NetworkEvent,
  regKeyEvent, urlMonitorEvent, dnsLookupEvent, imageLoadEvent.
  Supports all 7 conditions: is, contains, matches/regex, starts-with, ends-with,
  greater-than, less-than. Respects the negate and preserve-case attributes.
- Two-phase search — same architecture as Hunt:
    Step 1 (aggregation): single query combining all selected IOCs in one
    bool.should produces an Affected Hosts table showing host, maGuid,
    systemUniqueID, event count, first seen, last seen.
    Step 2: "Load matching events" fetches event cards on demand with pagination.
- Always exactly 2 OpenSearch queries regardless of how many .ioc files are selected.
  Client-side re-evaluation attributes each event to the specific IOC file(s) that
  matched, shown as labeled badges on every event card.
- Right-click cells in the Affected Hosts table for the standard context menu
  (Include / Exclude / Story Graph / Group By). Right-click First Seen / Last Seen
  to set a time >= / <= sidebar filter.
- Active sidebar filters and the current time range are applied to the search,
  so results are scoped to the same dataset as the main search.
- Malformed or empty .ioc files are skipped gracefully; unmapped OpenIOC fields
  are silently ignored without affecting the rest of the criteria.
- "No matching events found" message includes IOC count, total events searched,
  and search duration.
- Path traversal protection: the backend validates all requested .ioc paths resolve
  inside the OpenIOC/ directory before reading.


Version 26.08.0.124  (improvements since 26.06.0.67)


HUNT
----
- Paste free-form threat-intelligence text or structured CSV (Indicator_type,Data,Note)
  and run it as a single search across all configured IOC types in one click.
- IOC text is color-coded in-place inside the paste area as you type (CSS overlay).
- Saved Hunts: save the current IOC input under a name, reload or delete it at any
  time. Hunts persist in ets_explorer_custom.json and survive page reload.
- Two-phase architecture: Step 1 runs an aggregation-only query and shows the
  Affected Hosts table (host, maGuid, systemUniqueID, event count, first seen,
  last seen). Step 2 loads the matching event cards on demand via "Load matching
  events". Event counts and timestamps are accurate across the full time range,
  not just the fetched page.
- Right-click any cell in the Affected Hosts table (host/maGuid/systemUniqueID)
  to open the standard context menu — Include / Exclude filter, Story Graph,
  Add to Group By, etc.
- Right-click First Seen to add a "time ≥ this timestamp" sidebar filter;
  right-click Last Seen to add a "time ≤ this timestamp" sidebar filter.
- Right-click any field in a Hunt event summary row or the event detail panel
  opens the same context menu as in the Table view.
- Active sidebar filters and the current time range are applied when running a hunt,
  so the hunt is scoped to the same dataset as the main search.
- Per-field match operator (Equals, Contains, Starts with, Ends with) — configurable
  per field in Settings → Hunt Target Definitions. Changes save immediately.
- Wildcard path searches for Windows paths: backslash-escaped, case-insensitive,
  with a match_phrase fallback on the longest concrete segment for text-mapped fields.
- Path placeholders (<user>, <username>, <REDACTED>) are automatically converted
  to wildcard patterns so paths match regardless of the actual username.
- Hash auto-detection by length and hex format — no type keyword needed.
  SHA256 (64 chars), SHA1 (40 chars), MD5 (32 chars) all recognized automatically.
- CSV mode: extended type aliases (sha2, sha-256, sha-1, file_hash, etc.);
  hash type auto-detected from the value when the type column is unrecognized.
- IOC match badge in event cards shows the specific matched value.
  Stats bar shows unique host count across all returned events.
- Hunt results sorted oldest-first. Clicking a result card opens the full event
  detail panel on the right, same as in the Table view.


GROUP BY
--------
- New Group By tab: aggregate events by one or more fields without leaving the UI.
- Right-click any cell in the table, detail panel, or Hunt results and choose
  "Add to Group By" to send that field to the Group By tab instantly.
- Fields can also be typed manually in the Add field input.
- Single field uses a terms aggregation; multiple fields use multi_terms
  (OpenSearch 2.1+), combined with a separator in the results.
- Results table: value(s), event count with a proportional mini bar, unique host
  count (cardinality aggregation), first seen, and last seen timestamps.
- All column headers are sortable client-side — no re-fetch needed.
- Left-click a bucket row to apply that value as an equals filter and run a search.
- Right-click a bucket row to include or exclude the value from filters.
- "Apply current filters" checkbox scopes the aggregation to the same data as
  the main search (active sidebar filters + time filter).
- Top N selector: 10 / 25 / 50 / 100 / 250 / 500 buckets.
- Warning shown when sum_other_doc_count > 0 (more buckets exist than Top N).


SETTINGS & PERSISTENCE
-----------------------
- Hunt type definitions, column sets, and predefined filter defaults are stored in
  ets_explorer_core_setting.json in the app launch directory.
- Custom column sets, server groups, active group, and user-specific filters are
  stored in ets_explorer_custom.json.
- Hunt type definitions are editable in Settings → Hunt Target Definitions and
  changes write to disk immediately. "Reset to defaults" restores hardcoded defaults.
- All 8 built-in column sets (Default, Process, Network, File, DNS, Registry,
  ScheduleTask, Script) now have predefined filter templates.


FILTER PANEL
------------
- Filter panel split into two labeled sections:
    Custom filters     — added via +Add or right-click Include / Exclude.
                         Survive column set switches.
    Column set filters — predefined per column set, shown read-only.
                         Replaced automatically when the set changes.
- Column set filter rows have an editable value input for quick search-time
  customisation. Values reset on page reload; the field, operator, and logic
  are fixed by the column set definition.
- Switching a column set automatically triggers a new search.


TIME FILTER
-----------
- Custom range From / To inputs are now native date-time pickers (seconds precision).
- Timezone dropdown in the custom range section (default: browser local).
- Right-click "±5 min around event" and "+5 min after event" update the Time Filter
  inputs rather than adding filter rows.
- Right-click time filters use UTC values and auto-select UTC in the timezone picker.


TABLE VIEW
----------
- Timezone picker in the table toolbar (default UTC). Changing it re-renders the
  Time column immediately; selection is remembered across sessions.
- All returned results render in the table — no row cap.
- Column resize no longer accidentally triggers a column sort.
- Optimization tab is grayed out and disabled when a Server Group is active.


ACCESS LOG
----------
- HTTP access log written to access.log in the app launch directory.
  Rotates at 20 MB, keeps 5 backup files (~120 MB total history).
- Each line includes: timestamp (ms UTC), client IP:port, request line, status,
  response size, duration, X-Forwarded-For, X-Real-IP, X-Forwarded-Proto/Host/Port/
  Prefix, Host header, User-Agent, and Referer.
- Access lines go only to access.log — the main console log stays uncluttered.


CONNECTION
----------
- "Paste All Certificates" is the primary cert input. Paste the full output of
  the appliance "show certificates hxclient" command — CA cert, client cert,
  and private key are detected and saved automatically, encrypted at rest.
- Certificates encrypted with Fernet (AES-128-CBC + HMAC-SHA256) and stored as
  .enc files under certs/<server-name>/. Decryption happens in memory only.


LIVE TAIL
---------
- New events delivered via high-watermark polling with client-side _id deduplication
  so no event is ever missed regardless of timestamp precision.
- Only one poll runs at a time; the table sorts by Time descending when tail starts.
