Release Notes — OpenSearch UI
All changes since build 26.06.0.67
====================================

TIME FILTER
-----------
- From / To inputs are now date-time pickers (native browser picker, seconds precision).
- Timezone dropdown added to the custom range section (default: Browser local).
- Right-click "±5 min around event" and "+5 min after event" update the Time Filter
  sidebar section instead of adding a filter row to the query builder.
- Right-click time filters use UTC values and automatically select UTC in the
  timezone dropdown, matching the UTC timestamps shown in events.

TABLE VIEW
----------
- Timezone dropdown added to the table toolbar (beside the column set selector).
  Default is UTC. Changing the selection immediately re-renders the Time column.
  Selection is remembered across sessions.
- Resizing a column no longer accidentally triggers a column sort.
- Row display cap removed — all returned results now render in the table.
  Previously, results were silently capped at 250 rows.

CONNECTION SETTINGS
-------------------
- "Paste All Certificates" is the primary cert input. Paste the full output of
  "show certificates hxclient" — CA cert, client cert, and private key are
  detected and saved automatically, encrypted at rest.
- Individual .pem file paths moved to a collapsible sub-section (collapsed by default).
- "Pull certs from appliance" (SSH) feature removed.
- Certificates are encrypted using Fernet (AES-128-CBC + HMAC) and stored as
  .enc files in certs/<server-name>/. Decryption happens in memory only during
  the TLS handshake; temporary files are deleted immediately.

SERVER GROUPS
-------------
- Optimization tab is grayed out and disabled when a Server Group is selected
  (optimization is not available in group mode).

FILTER PANEL
------------
- Filter panel split into two labeled sections:
    "Custom filters"     — filters added via +Add or right-click Include/Exclude.
                           These survive column set switches.
    "Column set filters" — predefined filters for the active column set.
                           Replaced automatically when switching sets.
- Column set filters are displayed read-only (no edit inputs, no delete button),
  making clear they are managed by the column set, not the user.
- Switching a column set now automatically triggers a new search.
- Right-click Include on a numeric value uses the "equals" operator.
  Right-click Exclude on a numeric value uses "not_equals".
- Fixed: predefined filter field/value edits and delete in Settings were broken
  due to double-quoted attribute serialization. Now uses single-quoted strings.

COLUMN SETS
-----------
- "Column set" label added before the column set picker in the table toolbar.
- Registry Events — "Reg Key Name" column now displays both registry.keyName
  and registry.regKeyName combined in one cell (e.g. "HKLM\...\Key / ValueName").
  Right-click filtering still targets registry.keyName.

PREDEFINED FILTERS
------------------
- All 8 built-in column sets now have predefined filter templates
  (previously only Default, Process, File, and DNS had defaults).

  DNS Events:
    OR  eventType equals "DNS Query"
    OR  eventType equals "Network Accessed"
    AND dns.name, network.dnsNames.name contains (empty)

  Default:
    AND host contains (empty)
    OR  cmdLine contains (empty)

  Process Events:
    AND pFullName contains (empty)

  File Events:
    AND eventType contains "File"
    OR  fileAttributes.path contains (empty)
    OR  fileAttributes.md5 contains (empty)

  Network Events:
    OR  eventType contains "network"
    OR  eventType contains "dns"
    AND network.dstIp contains (empty)
    AND network.dstPort equals (empty)
    AND network.protocol contains (empty)

  Registry Events:
    OR  eventType contains "reg"
    OR  registry.keyName, registry.regKeyName contains (empty)
    AND registry.keyValueName contains (empty)
    AND registry.keyValueName contains (empty)

  ScheduleTask Events:
    AND eventType contains "schedule"
    AND schedtask.author contains (empty)
    AND schedtask.name contains (empty)
    AND schedtask.description contains (empty)
    AND schedtask.commands contains (empty)

  Script Events:
    AND eventType contains "script"
    AND scripts.intentions.name contains (empty)
    AND scripts.intentions.lines contains (empty)

- Built-in column set predefined filters always reload from code-defined defaults
  on page load. Changes made in Settings during a session are not persisted for
  built-in sets, ensuring updates to defaults take effect automatically on refresh.
- Column set filter rows now have an editable value input. The field, operator, and
  AND/OR logic remain fixed (defined by the column set); only the value can be typed
  in at search time. Values are not saved — they reset on page reload.

FILTER PANEL (continued)
------------------------
- Fixed: right-clicking the User column and selecting Include/Exclude previously
  inserted "[object Object]" as the filter value. The filter now correctly targets
  user.name with the actual username (e.g. "Joe"). Manual filters on user.name
  also work correctly.

UI
--
- Search box placeholder updated to "contains search on all fields".
- Help text below the search box updated to: "The search can be fast if the Time
  filter is applied or the search using filters on specific columns is much faster".
- Horizontal separator added above the Output section for visual clarity.
- Hint added below the Filters section header: "Select fields from Event Details
  by right click".

OPTIMIZATION
------------
- "Use filters" checkbox added to the Optimization settings bar. When checked,
  the active sidebar filters (custom and column set) and the time range are applied
  to the aggregation query, scoping results to the same data as the main search.
  When unchecked (default), the aggregation runs across all data as before.

BUG FIXES
---------
- Fixed: starting the app with cert paths pointing to .enc files from a previous
  installation (encrypted with a different key) caused a crash — the app tried to
  load the raw encrypted binary as a PEM certificate. The app now skips the CA cert
  load gracefully and logs a clear message to re-save the certificates in Settings.
  Client cert/key decryption failure is also handled without crashing.

LIVE TAIL
---------
- Fixed: tail polling stopped returning new events after the first update. Root cause:
  the high-watermark filter used "greater than" (exclusive), which silently dropped any
  new events that share the same timestamp as the last seen event. Changed to "greater
  than or equal" with client-side de-duplication by document _id, so no events are
  ever missed regardless of timestamp precision.
- Fixed: concurrent poll executions could overlap when the poll interval is shorter
  than the round-trip time. Added a guard so only one poll runs at a time.
- Table is now automatically sorted by Time descending when tail mode starts, so the
  newest events are always visible at the top. Sort is cleared when tail stops.
